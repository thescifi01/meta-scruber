Files are read and rewritten entirely in your browser's memory.

Images

JPG, PNG, WEBP and GIF files are decoded and redrawn onto a blank canvas, then re-encoded from scratch. Only pixels survive that trip — EXIF, XMP, IPTC, and any text chunks are left behind. GIFs are flattened to their first frame.

Video

MP4, MOV and M4V files are rewritten at the container level: the udta and meta boxes (where GPS, device info, and encoder tags live), plus padding boxes, are cut out entirely, and creation/modification timestamps in the file's header are zeroed. Audio and video data are copied bit-for-bit — no re-encoding, no quality loss. Other containers (WebM, AVI, MKV) aren't supported yet, and a file is only offered for download if this rewrite can be done safely.

AI-generation check

Before stripping anything, the file is checked for provenance signals: IPTC/C2PA "Digital Source Type" declarations, Content Credentials (C2PA) blocks, and generator names left behind by tools like Midjourney, Stable Diffusion, ComfyUI, or Adobe Firefly in EXIF/XMP/PNG-text/MP4-metadata fields. This is metadata inspection, not image analysis — it can only report what a file's own tags claim about themselves, so it can't catch an AI image with metadata already removed, and (rarely) a tag could be forged. Note that scrubbing removes these provenance tags along with everything else, including legitimate C2PA disclosures.

Why local

The file never touches a server. If it did, "removing your metadata" would just mean moving it somewhere else.
